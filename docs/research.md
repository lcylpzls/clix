# 竞品调研

> 结论先行：本生态为自用，不需要兼容第三方 CLI 协议的“替换即兼容”能力，
> 因此 clix 不实现 cobra/urfave/kong 的兼容层，只吸收它们经过验证的设计思想，
> 并围绕 errx/logx/confx/validx 家族形成自己的协议：确定性、可测试、家族一致。

## 调研对象

| 库 | 定位 | 值得借鉴 | 自用场景下的短板 |
| --- | --- | --- | --- |
| cobra（spf13） | 命令树 + pflag 的完整框架 | 命令树、自动帮助、版本/补全能力、生态心智 | 体量偏大，错误处理与日志体系自成一套；pflag 语法兼容层对我们没有收益 |
| urfave/cli v3 | 声明式子命令框架 | 子命令/别名/flag/环境变量/钩子的声明式组合 | 反射与隐式行为多，输出流与日志需自行接入；pre-1.0 接口变更频繁 |
| kong | struct tag 驱动的参数框架 | 类型安全、tag 映射、可校验 | 魔法重（反射解析），动态/流式场景弱；错误文本与家族错误码脱节 |
| 标准库 flag | Go 官方参数解析 | 语法稳定、零依赖 | 无子命令树、无帮助约定、类型有限，不足以支撑生态 CLI |

## 自研协议原则

1. **显式优于魔法**：命令、参数、钩子全部用代码显式声明；
   struct tag 反射仅在 confx/validx 联动层作为可选项提供。
2. **确定性输出**：帮助文本、错误文本、退出码都有稳定约定，可快照断言。
3. **无全局状态**：不使用包级可变配置；App 实例即全部状态，可并行构造。
4. **家族错误码**：一切失败走 errx 结构化错误码，日志走 logx，
   参数校验复用 validx，配置加载复用 confx。
5. **可测试性**：Out/Err/Logger 均可注入，`Execute` 只返回退出码，
   不隐式调用 `os.Exit`，测试无需子进程。
